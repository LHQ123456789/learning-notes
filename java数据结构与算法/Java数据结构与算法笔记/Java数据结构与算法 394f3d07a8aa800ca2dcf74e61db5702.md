整理「堆操作的复杂度表」+ 堆的数组表示（parent/leftChild/rightChild 索引公式）

**一、堆操作的复杂度总表**

| **操作** | **时间复杂度** | **说明** |
| --- | --- | --- |
| **建堆（Heapify）** | **O(n)** | 从最后一个非叶节点向下调整，n 个元素整体建堆 |
| **插入（Push / Insert）** | **O(log n)** | 先放末尾，再向上调整（上浮） |
| **删除堆顶（Pop / Extract-Max/Min）** | **O(log n)** | 末尾替换堆顶，再向下调整（下沉） |
| **获取堆顶（Top / Peek）** | **O(1)** | 直接返回数组第一个元素 |
| **删除任意元素** | **O(log n)** | 先将要删除的元素与末尾交换，然后根据情况上浮或下沉 |
| **修改任意元素** | **O(log n)** | 修改后根据新值决定上浮或下沉 |
| **查找任意元素** | **O(n)** | 堆不是搜索结构，需要遍历整个数组 |
| **合并两个堆（Merge）** | **O(n)**（普通二叉堆）
**O(log n)**（左倾堆/二项堆/斐波那契堆） | 普通二叉堆需要合并两个数组再建堆 |

> **关键记忆点**：堆的三种基本操作（建堆 O(n)、插入 O(log n)、删除堆顶 O(log n)）复杂度差异很大，**建堆的 O(n) 是反直觉但必须记住的重点**——很多人会误以为是 O(n log n)。

**二、堆的数组表示**

堆用数组存储时，**下标从 0 开始**，按照完全二叉树的层序遍历存放。

**核心索引公式（从 0 开始）**

| **关系** | **公式** | **约束条件** |
| --- | --- | --- |
| **父节点** | `parent(i) = (i - 1) // 2` | i > 0 |
| **左孩子** | `leftChild(i) = 2 * i + 1` | 必须 < heapSize |
| **右孩子** | `rightChild(i) = 2 * i + 2` | 必须 < heapSize |
| **最后一个非叶节点** | `lastNonLeaf = heapSize // 2 - 1` | heapSize > 0 |

**图解示例：最大堆 `[50, 30, 40, 10, 20, 35, 25]`**

text

```
数组下标:     0      1      2      3      4      5      6
元素值:      50     30     40     10     20     35     25

对应的完全二叉树:
               50 (0)
              /      \
           30 (1)    40 (2)
          /    \     /    \
       10 (3) 20(4) 35(5) 25(6)
```

**验证公式**：

- `parent(3) = (3-1)//2 = 1` ✅ 10 的父节点是 30
- `leftChild(1) = 2*1+1 = 3` ✅ 30 的左孩子是 10
- `rightChild(1) = 2*1+2 = 4` ✅ 30 的右孩子是 20
- `lastNonLeaf = 6//2 - 1 = 2` ✅ 最后一个非叶节点下标是 2（值为40）

**三、为什么建堆是 O(n) 而不是 O(n log n)？**

很多初学者会疑惑：每个元素插入要 O(log n)，n 个元素难道不是 O(n log n)？

**关键区别**：

- **逐个插入建堆**：n 个元素每个执行一次插入 → **O(n log n)**
- **自底向上建堆（Heapify）**：从最后一个非叶节点开始，向根方向逐步下沉 → **O(n)**

数学直觉：**靠近底层的节点数量多，但下沉的距离短**（最多 1 层）；靠近根部的节点数量少（仅 1 个），但下沉距离长（最多 log n 层）。总的操作次数 ≈ n，而不是 n log n。

### 整理「TopK 问题解题模板」：堆解法 vs 快排 partition 解法

**一、问题定义**

**TopK 问题**：从 n 个元素中找出**第 K 大**（或第 K 小）、或**前 K 大**（前 K 小）的元素。

常见变体：

- 数组中第 K 个最大元素（LeetCode 215）
- 前 K 个高频元素（LeetCode 347）
- 数组中的第 K 个最大元素 / 最小的 K 个数（剑指 Offer 40）
- 数据流中的第 K 大元素（LeetCode 703，用堆维护）

---

**二、两种核心解法对比**

| **维度** | **堆解法** | **快排 partition 解法** |
| --- | --- | --- |
| 时间复杂度 | O(n log k) | 平均 O(n)，最坏 O(n²) |
| 空间复杂度 | O(k) | O(1)（原地） |
| 是否修改原数组 | 否 | 是 |
| 适合场景 | 数据流 / 海量数据 / n 很大 k 很小 | 一次性静态数组，追求最快 |
| 稳定性 | 不涉及 | 不涉及 |
| 最坏情况 | 稳定 O(n log k) | 可能退化，需随机化基准 |
| 返回前 K 个 | 天然支持 | 需要额外整理 |

---

**三、堆解法模板**

**核心思想**

- 求**第 K 大 / 前 K 大**：维护一个**大小为 K 的小顶堆**。
    - 堆顶是当前 K 个元素中最小的，新元素比堆顶大就替换。
    - 遍历完，堆里就是最大的 K 个，堆顶是第 K 大。
- 求**第 K 小 / 前 K 小**：维护一个**大小为 K 的大顶堆**。

> 记忆口诀：**求大用小顶堆，求小用大顶堆**（堆顶是"淘汰线"）。
> 

**Java 模板（第 K 大）**

java

```java
public int findKthLargest(int[] nums, int k) {
    // 小顶堆，默认就是小顶堆
    PriorityQueue<Integer> heap = new PriorityQueue<>();

    for (int num : nums) {
        heap.offer(num);
        if (heap.size() > k) {
            heap.poll(); // 弹出最小的，保留最大的 k 个
        }
    }

    return heap.peek(); // 堆顶即第 k 大
}
```

**求前 K 大（返回数组）**

java

```java
public int[] topK(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    for (int num : nums) {
        heap.offer(num);
        if (heap.size() > k) heap.poll();
    }
    int[] res = new int[k];
    for (int i = 0; i < k; i++) res[i] = heap.poll();
    return res;
}
```

**求前 K 小（大顶堆）**

java

```java
public int[] topKSmallest(int[] nums, int k) {
    // 大顶堆
    PriorityQueue<Integer> heap = new PriorityQueue<>((a, b) -> b - a);
    for (int num : nums) {
        heap.offer(num);
        if (heap.size() > k) heap.poll();
    }
    int[] res = new int[k];
    for (int i = 0; i < k; i++) res[i] = heap.poll();
    return res;
}
```

**复杂度**

- 时间：每个元素入堆 O(log k)，共 n 个 → **O(n log k)**
- 空间：堆大小 k → **O(k)**

**四、快排 partition 解法模板**

**核心思想**

利用快排的 `partition` 操作：

- 每轮 partition 后，基准元素归位到下标 `p`。
- 若 `p == n - k`（第 K 大的位置），直接返回。
- 若 `p < n - k`，说明目标在右半部分，只递归右边。
- 若 `p > n - k`，说明目标在左半部分，只递归左边。

> 关键：**只递归一边**，所以平均时间复杂度从 O(n log n) 降到 **O(n)**。
> 

**Java 模板（第 K 大，随机化基准）**

java

```java
class Solution {
    public int findKthLargest(int[] nums, int k) {
        int n = nums.length;
        int target = n - k; // 第 k 大 = 升序后下标 n-k
        return quickSelect(nums, 0, n - 1, target);
    }

    private int quickSelect(int[] nums, int left, int right, int target) {
        int p = partition(nums, left, right);
        if (p == target) {
            return nums[p];
        } else if (p < target) {
            return quickSelect(nums, p + 1, right, target);
        } else {
            return quickSelect(nums, left, p - 1, target);
        }
    }

    private int partition(int[] nums, int left, int right) {
        // 随机选基准，避免最坏 O(n²)
        int randomIndex = left + (int)(Math.random() * (right - left + 1));
        swap(nums, left, randomIndex);

        int pivot = nums[left];
        int i = left + 1, j = right;

        while (true) {
            while (i <= j && nums[i] < pivot) i++;
            while (i <= j && nums[j] > pivot) j--;
            if (i > j) break;
            swap(nums, i, j);
            i++;
            j--;
        }

        swap(nums, left, j);
        return j;
    }

    private void swap(int[] nums, int i, int j) {
        int t = nums[i];
        nums[i] = nums[j];
        nums[j] = t;
    }
}
```

**迭代版（避免递归）**

java

```java
public int findKthLargest(int[] nums, int k) {
    int n = nums.length;
    int target = n - k;
    int left = 0, right = n - 1;

    while (true) {
        int p = partition(nums, left, right);
        if (p == target) return nums[p];
        else if (p < target) left = p + 1;
        else right = p - 1;
    }
}
```

**复杂度**

- 时间：平均 **O(n)**，最坏 O(n²)（随机化后几乎不会出现）
- 空间：O(1) 原地（递归版 O(log n) 栈）

**五、如何选择？**

| **场景** | **推荐解法** | **原因** |
| --- | --- | --- |
| 数据流 / 动态添加 | **堆** | 快排需要全部数据 |
| n 很大，k 很小 | **堆** | O(n log k) 远小于 O(n) |
| 一次性静态数组，追求最快 | **快排 partition** | 平均 O(n) |
| 不允许修改原数组 | **堆** | partition 会打乱数组 |
| 要求稳定 O(n log n) | **堆** | 快排最坏 O(n²) |
| 内存受限 | **快排 partition** | O(1) 空间 |

**BST操作复杂度详解**

**1. 查找操作 (Search)**

**时间复杂度分析**：

- **平均**：O(log⁡n) — 树接近平衡，高度约为 log⁡2nlog2*n*
- **最坏**：O(n)— 树退化为链表，高度为 n*n*
- **最好**：O(1)— 根节点就是目标

**空间复杂度**：O(h) — 递归调用栈（迭代版本为 O(1)

---

**2. 插入操作 (Insert)**

**时间复杂度分析**：

- **平均**：O(log⁡n)— 需要先查找位置（查找路径长度）
- **最坏**：O(n) — 退化为链表
- **最好**：O(1) — 直接插入根节点位置

**特点**：

- 插入总是发生在叶子节点
- 不涉及节点移动（与AVL树不同）

---

**3. 删除操作 (Delete)**

**三种情况**：

| **情况** | **操作** | **时间复杂度** | **说明** |
| --- | --- | --- | --- |
| **叶子节点** | 直接删除 | O(1) | 置为None |
| **一个子节点** | 子节点替换 | O(1) | 绕过当前节点 |
| **两个子节点** | 找后继/前驱替换 | O(log⁡n) | 需额外查找 |

**整体时间复杂度**：

- **平均**：O(log⁡n)— 查找 + 删除
- **最坏**：O(n)— 退化为链表

### AVL平衡树

- **平衡因子** = 左子树高度 - 右子树高度
- 合法值：{-1, 0, 1}
- 失衡时需要进行旋转

## **四种旋转总结对比表**

| **旋转类型** | **简称** | **触发条件** | **操作顺序** | **结果** |
| --- | --- | --- | --- | --- |
| **LL** | 右旋 | 在左子树的**左**孩子插入 | 一次右旋 | 高度降低 1 |
| **RR** | 左旋 | 在右子树的**右**孩子插入 | 一次左旋 | 高度降低 1 |
| **LR** | 先左后右 | 在左子树的**右**孩子插入 | 左旋左孩子 → 右旋根 | 高度降低 1 |
| **RL** | 先右后左 | 在右子树的**左**孩子插入 | 右旋右孩子 → 左旋根 | 高度降低 1 |
